在 swiper-task.html 里，生成 new Swiper('#wySw4', { }) 里面的配置对象。要求开启无缝循环，自动轮播时长 3.2 秒，并且用户手动滑动、点击操作之后，自动轮播不会停止。添加可点击的圆点分页器，切换动画初始效果设置为 cube。只输出大括号内的配置代码，不需要引入 js、不需要外层 new Swiper，不要多余解释。

新增一句约束→ 其余措辞完全不动→ AI 输出结构不变

需求点第 1 轮是否写明第 2 轮是否写明落到代码上

迭代分析

第一轮漏掉的是"手动操作后自动轮播不停止"。提示词只说了"自动轮播时长 3.2 秒"，没说被打断之后怎么办。第一轮的答案恰好带上了 disableOnInteraction: false，但这是模型的默认写法，不是需求驱动的结果——换一个模型或换个问法就可能省略该字段，此时 Swiper 的默认行为会在用户拖动后停掉自动播放，需求就静默失败了。

第二轮的做法不是重写，而是精准补一句。原句"自动轮播时长 3.2 秒"后面追加"并且用户手动滑动、点击操作之后，自动轮播不会停止"，把隐性默认变成显性约束；其余四句一字不改，所以第二轮输出与第一轮结构完全一致，不会引入新变量，便于定位"这一句到底改变了什么"。

仍然存在的漏洞：没给参数白名单。speed: 800 是我没要求、AI 自行补的。凡是提示词没约束的参数，模型都会替你决定。要完全可控，应加一句"只允许出现 loop / effect / autoplay / pagination 四个键"。

验证方式：把配置粘进 new Swiper('#wySw4', { ... }) 后逐项实测——自动切换间隔约 3.2 秒；按住拖动松手后自动播放继续推进；四个圆点可点击跳转；刷新后首屏为 cube 的 3D 翻转。

任务二

creative 仿写：课堂没讲，AI 教你

★★
第 1 轮提示词

请打开 swiper/demo/257-effect-creative.html，配合 AI 读懂 creativeEffect 的 transform 写法，为演示四新增第 7 个按钮「creative 电影墙」。 效果要求：上一张缩小左移并带角度、下一张放大右移进场（参数自定，但要"像电影选片墙"）。

creativeEffect: {
  prev: { shadow: true, translate: ['-45%', 0, -220], rotate: [0, 22, 0], scale: 0.8 },
  next: { shadow: true, translate: ['62%', 0, -180], scale: 0.86 }
}
第 2 轮提示词（追问）

prev / next 的 transform 各控制什么？

先让它做出来→ 再让它讲清楚→ 用自己的话复述

迭代分析

第一轮把"感觉"翻译成参数。"像电影选片墙"是视觉描述，模型无法直接执行，真正起作用的是我同时给出的官方示例路径——它提供 prev/next 的字段格式（translate 用百分号 + 像素、rotate 用角度），我只需要把"缩小左移带角度""放大右移进场"分别映射到 prev 和 next，数值自己调。

第二轮换了一种迭代方向：不是改代码，而是追问语义。任务一迭代的是"需求→代码"，这里迭代的是"代码→理解"。追问之后才弄清：prev 管的是索引小于当前项的那张（已滑过、留在左侧），next 管的是索引大于当前项的那张（还没进来、停在右侧）；所谓"新图放大进场"其实是 next 的反向过程，也就是从 next 的位置回到正位。

关键坑：translate 里的百分号是相对幻灯片自身尺寸，不是相对容器；z 轴只能用像素。所以同一个 '-45%' 在宽屏和窄屏下视觉位移不同，但"移出比例"是一致的，这正是选片墙效果能自适应宽度的原因。

验证方式：点第 7 个按钮后读实例的 effect 是否为 creative；检查非激活幻灯片的内联样式是否含 matrix3d（rotateY 与 translateZ 生效）；再切回 slide，确认 matrix 恢复且自动播放仍在运行。

任务三

综合创作 + 技术答辩：超纲加分项

★★★
第 1 轮提示词

两件事：① 为光影展添加第六件展品爱达·魔都号（首艘国产大型邮轮，2024 年 1 月首航），图片用 AI 生成（横版 16:9），slide 结构完整；② 挑一个课堂上没讲过的 Swiper 能力加上去：keyboard 键盘控制 / mousewheel 滚轮 / zoom 双击缩放 / parallax 视差，任选其一

keyboard: {
  enabled: true,          // 开启键盘控制
  onlyInViewport: true,   // 仅在轮播处于视口内时响应
  pageUpDown: false      // 不抢占 PageUp / PageDown
}
第 2 轮提示词（素材替换）

将爱达魔都号图片换成我这张图片

首轮靠文字描述氛围→ 验收不通过→ 直接给素材替换

迭代分析

提示词从"生成代码"升级为"生成交付物"。任务三一句里塞了四层要求：素材（AI 生成 16:9）、内容（船名与首航时间要准确）、结构（slide 结构完整）、能力（自选一个未讲 API）。这比任务一的单点参数复杂，但也更依赖验收标准——所以我给的是"四个演示台都要有第 6 张 slide"，而不是"加一张图"。

第二轮暴露了文生图的边界。图片类需求首轮只能用文字描述氛围（"金色时刻、深蓝海面、船艏清晰"），生成结果是否满足"像首艘国产大型邮轮"无法靠提示词保证，只能人工比对。迭代方式因此变成"直接给素材"，把生成的 2730×1536 PNG 转成 JPG 覆盖同名文件——因为 HTML 里引用的是固定文件名，替换素材不需要改任何代码，这也是当初坚持用语义化文件名的收益。

为什么选 keyboard 而不是另外三个：mousewheel 会抢占页面滚动，zoom 需要额外的容器与手势提示，parallax 需要多层视差素材；keyboard 只需一个配置对象、零额外 DOM，还额外加了 onlyInViewport 与 pageUpDown: false 两个防护，避免滚出屏幕后仍响应方向键、避免和整页翻屏快捷键打架。

验证方式：四个轮播的 slides.length 均为 6；aida_modu.jpg 请求成功且 naturalWidth 正确；分页器圆点数同步为 6；在视口内按 ← → 索引确实前进；控制台无 JS 报错。

三个任务提示词的迭代主线

  1. 任务一：把隐含默认写成明文。第一轮四句需求都写了，唯独"被打断后是否继续"是空白，模型用默认值替我做主。第二轮只补这一句，其余不动——迭代的最小单位应该是"一条约束"，不是"整段重写"。
  2. 任务二：从"能做"到"能讲"。代码跑通不等于掌握，追问 prev/next 的语义后才知道参数为什么这么填。对没讲过的 API，正确的迭代是"示例 + 追问"，而不是让 AI 一次性写完。
  3. 任务三：从"代码"到"交付物"。需求变成多目标（素材 + 内容 + 结构 + 能力）后，必须同时给出验收判据；素材类需求首轮无法精确控制，迭代手段是替换资源而不是重写提示词。

共三条通用结论：未写进提示词的约束，等于交给模型随机决定；每条需求都要配一条可实测的判据；第二轮的补充应指向第一轮的具体缺口。
